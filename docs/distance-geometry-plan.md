# FishRadar 用画面几何判断相对远近

默认沿用现有 Vision 上半身框。用框高判断当前显得多近，用同一个人的框高和框宽变化判断靠近趋势，用位置关联轨迹、判断左右，并在已有重点区内提高靠近判断的灵敏度。用户可沿用原来的坐姿、机位和区域设置。米制距离暂时不作为提示条件。

## v0.2.2 实际提醒

- 现用规则按最近三次观测中第二大的有效尺寸分档。有效尺寸取框高与三倍框宽的较小值。达到 32% 会提示近处，达到 42% 会提示更近。连续变大的框也可能提前触发黄灯。
- 取景稳定时，新轨迹首帧的有效尺寸达到 50% 就亮红，即使框贴边也可以使用这项判断。正在追踪的目标仍需连续帧确认升级，避免单帧变大的框误触发。
- 一个宽度不超过画面 10%、有效尺寸不超过 20% 的框，在同一位置反复出现且尺寸变化很小时，可以进入固定框记忆。超过静止等待时间后，现用与候选规则各自压制该框的重复绿灯。目标明显移动或变大时恢复判断，超过 60 秒未匹配的记忆会失效。
- 同一条轨迹贴边时，已确认的黄红灯最多延续到最后一次完整观测后 0.6 秒。取景变化会清除保级证据。贴边后的框如果裁得很窄，可能仍缺少升级证据。
- 现用规则控制实际提醒和自动切换。候选规则复用同一批人员框和轨迹，开启实验监控后用于对照。

距离辅助线标出 32% 与 42% 的尺寸参考，候选规则按自己的框高门槛对照。比例以画面为基准，实际灯色仍取决于框宽和连续帧证据。

## 哪些信号能用于判断

- **同人、同镜头、姿态相近。** 针孔投影近似为 `h = fy × H / Z`，所以相邻时段的深度比约为 `Z2 / Z1 = h1 / h2`。看同一人的变化时，人体尺寸和焦距可以约掉。转身、弯腰、遮挡会改变框的可见尺寸。用框宽变化核对靠近趋势，静态近处判断仍以框高为主，避免侧身变窄时过早丢失提醒。公式和假设见[几何资料](monocular-geometry-sources.md)。
- **画面位置。** 左右坐标用来判断箭头方向。在有明显纵深的过道里，现有重点区能表达哪些位置值得关注。横坐标单独只能说明目标在哪条视线上。已有重点区继续作为靠近的辅助线索。脚可见且场景有可靠地面参照时才考虑地面投影，当前的上半身框无法提供脚的位置。
- **相机设置。** 本机 SDK 将常用的逐帧内参派送和相机格式视场角接口标为原生 macOS 不可用。用与 FishRadar 相同的 `.medium` 预设建立未启动的摄像头会话时，其活动格式描述也没有公开的水平视场角字段。现版在画面尺寸变化或人物居中开启时清理候选距离历史，诊断会标记取景不稳。缺少可靠的变化信号时，框本身无法区分变焦和人靠近。见 [Apple Mac 示例的焦距读取说明](https://github.com/apple-aiml-research/ml-depth-pro-2/blob/main/demo/apple/Sources/demo/Camera.swift)。

## 实验候选规则

1. 沿用使用者过滤、忽略区和检测节奏。用轨迹累计证据，关联不确定时重新确认。候选规则遇到边缘截断时沿用同一轨迹已确认的灯色，最多保留至最后一次完整观测后 0.6 秒。已知取景变化会清除这项证据。
2. 连续三次观测中至少有两次支持相应大小才升级。框高用于近处和更近分档。按现有预览的测试范围，原型的黄灯进入阈值为画面高度的 32%，红灯为 45%。退出阈值分别放宽到 25% 和 40%，用于抑制来回闪烁。这些是回放初值，随未知人体尺寸和取景变化会偏移。
3. 同一个人持续变大时，比较最近两次观测与早期尺寸。如果框高和框宽共同增长、增长比例相近，且目标已达到基本大小，可以提前亮黄。靠得很近时的横向经过无需出现增长。黄红解除仍要看轨迹和距离，固定工位的静止过滤继续生效。

## 查看诊断

1. 在「设置 → 检测区域与预览」中勾选「显示距离辅助线」，再打开「实验监控」并开启监控。完整预览显示蓝色头框、红色上半身框、青色参与检测框，以及两套规则的灯色。自身头部标注在可见的详细预览或带辅助线抓拍时尝试用脸的位置校准。其他人员的独立检测框仍按区域规则参与判断。
2. 用「打开记录文件夹」找到 `diagnostics.jsonl`。对照结果或判断原因变化时写入 `distance_comparison`。其中 `red_evidence` 的 `height`、`width` 和 `screen_x` 都以画面比例表示。该字段还包含两套灯色、是否贴边、是否在当前帧检出及红灯判断原因。
3. `strong_first_frame` 表示新目标首帧的尺寸已足以亮红，`width_limited` 表示框高足够但有效尺寸受框宽限制，`frame_edge` 表示候选受到边缘裁切限制，`edge_hold` 表示暂时延续此前确认的等级，`repeated_small_box` 表示重复绿灯被抑制。若需要核对某次触发的画面，可单独开启「保存诊断照片（仅本机）」。
4. 「照片上限（张）」默认是 200，可在「实验监控」调整，结束编辑即保存。抓拍达到上限后停止，资源与距离日志继续记录。抓拍样本反映已经触发的提醒，漏报评估需要独立记录实际经过事件。

## 可重复的验证

仓库的 [Swift 合成回放](../Experiments/DistanceGeometry/main.swift) 用理想相机把有已知位置和大小的人投影成检测框，再把同样的框交给现有预览版和候选距离规则。每帧间隔 0.4 秒。运行方式：

```sh
swiftc Sources/ApproachTracker.swift Experiments/DistanceGeometry/main.swift -o /tmp/fishradar-geometry-replay
/tmp/fishradar-geometry-replay
```

| 合成场景 | 现有预览 | 几何候选 |
| --- | --- | --- |
| 远处横穿、经过画面边缘 | 绿 | 绿 |
| 近处横穿 | 绿 | 两次观测后黄 |
| 很近处直接出现 | 两次观测后黄 | 两次观测后红 |
| 正常向前走近 | 第四次观测黄 | 第三次观测黄 |
| 近处转身变窄 | 绿 | 保持近处提醒 |
| 从近处退远 | 绿 | 两次远处观测后恢复绿色 |
| 已知画面放大，人物距离不变 | 黄 | 绿 |

回放覆盖十一种场景。附加的几何测试验证了两组歧义。大小不同的人可以在不同距离产生相同的框，已知人物的框也可以在视角放大和实际走近时完全相同。「已知画面放大」由测试显式提供信号，实际应用还需验证能观察到哪些取景变化。回放采用已知单人轨迹，未测 Vision 漏检、使用者过滤、中途遮挡和多人身份关联。

[追踪回归测试](../Tests/main.swift) 还覆盖了近处贴边首帧亮红、走远后依次降为黄和绿，以及细长框、取景不稳和已有轨迹的单帧跳变。

实景验收可以自己录几段离线素材，用地面标记只给测试打分。覆盖普通和广角画面、近处横穿、远处活动、转身、遮挡及多人交错。先对同一批素材量化误报次数、漏报次数、首次黄红延迟，再在同一台 Mac 上用已有监控比较 CPU 和常驻内存。验收时优先看会触发自动切换的黄红判定。等近处漏报和远处误报都优于现有预览，再启用新规则。
